# data lifecycle (it)

- create
  - dữ liệu được sinh ra từ input, event, api
  - dùng để xác định nguồn gốc và trách nhiệm tạo dữ liệu

- validate
  - kiểm tra schema, format, business rule
  - dùng để loại dữ liệu sai trước khi xử lý sâu

- process
  - transform, enrich, tính toán dữ liệu
  - dùng để tạo giá trị mới từ dữ liệu thô

- persist
  - ghi dữ liệu vào storage lâu dài (db, file, object store)
  - dùng để đảm bảo dữ liệu tồn tại sau request/process

- retrieve
  - đọc dữ liệu đã persist để sử dụng lại
  - dùng để phục vụ nghiệp vụ, báo cáo, truy vết

- update
  - thay đổi dữ liệu đã tồn tại
  - dùng để phản ánh trạng thái mới của nghiệp vụ

- archive
  - chuyển dữ liệu ít dùng sang storage rẻ hơn
  - dùng để giảm tải hệ thống chính

- delete
  - xóa dữ liệu khỏi hệ thống
  - dùng để tuân thủ chính sách, giảm rủi ro, giảm chi phí

# lỗi msb3030 – swashbuckle
## triệu chứng
- build fail với lỗi `msb3030 could not copy file`
- thiếu file `swashbuckle.aspnetcore.swaggergen.dll`
- warning `net6.0 out of support` (không làm fail build)

## nguyên nhân
- nuget package chưa được restore
- cache nuget bị hỏng / thiếu file
- lỗi môi trường build, không phải code

## cách xử lý (thứ tự loại nhanh)
- xoá cache nuget  
  - `dotnet nuget locals all --clear`
- restore lại dependency  
  - `dotnet restore`
- kiểm tra `.csproj` có reference  
  - `swashbuckle.aspnetcore 6.5.0`
- vẫn lỗi → xoá thư mục package  
  - `c:\users\phuhu\.nuget\packages\swashbuckle.aspnetcore.swaggergen`
- build lại

# chọn port trống, không xung đột
- xem toàn bộ port đang dùng
  - `netstat -ano | findstr LISTENING`
  - `netstat -ano | findstr LISTENING | sort`
  - port xuất hiện → loại

- kiểm tra port cụ thể
  - `netstat -ano | findstr :<port>`
  - có output → loại

- kiểm tra port bị windows reserve
  - `netsh int ipv4 show excludedportrange protocol=tcp`
  - nằm trong range → loại

- quyết định dùng port
  - >1024
  - không xuất hiện ở 3 bước trên
  - dùng ngay

- gợi ý
  - ưu tiên 5000–5999 hoặc 7000–7999

# hướng dẫn quản lý vòng đời windows service bằng file .bat

## mục tiêu
- quản lý service theo vòng đời: "install → start → running → pause/continue → stop → uninstall"
- mỗi file = 1 hành động
- không dùng đường dẫn tuyệt đối

## cấu trúc thư mục khuyến nghị
- service/
    - myservice.exe
    - scripts/
        - install.bat
        - start.bat
        - status.bat
        - pause.bat
        - continue.bat
        - stop.bat
        - uninstall.bat

## nguyên tắc đường dẫn
- script chạy từ thư mục scripts
- dùng "%~dp0" để lấy thư mục hiện tại của file .bat
- exe nằm ở "../myservice.exe"

## install.bat

```bat
@echo off
set service_name=myservice
set service_bin=%~dp0..\myservice.exe

sc create %service_name% binpath= "%service_bin%" start= auto
````

## start.bat

```bat
@echo off
set service_name=myservice

sc start %service_name%
```

## status.bat

```bat
@echo off
set service_name=myservice

sc query %service_name%
```

## pause.bat

```bat
@echo off
set service_name=myservice

sc pause %service_name%
```

## continue.bat

```bat
@echo off
set service_name=myservice

sc continue %service_name%
```

## stop.bat

```bat
@echo off
set service_name=myservice

sc stop %service_name%
```

## uninstall.bat

```bat
@echo off
set service_name=myservice

sc stop %service_name% >nul 2>&1
sc delete %service_name%
```

## cách sử dụng

* chạy cmd với quyền administrator
* cd vào thư mục scripts
* chạy từng file theo nhu cầu

## tiêu chí loại

* không cần pause/continue → bỏ 2 file tương ứng
* không cần auto start → bỏ "start= auto"

## lỗi thường gặp

* service không start → kiểm tra exe có chạy độc lập không
* binpath sai → echo %service_bin% để debug

## kết luận

* tách file = giảm nhầm lệnh
* đường dẫn tương đối = dễ deploy, dễ copy môi trường
* đủ chuẩn dùng cho prod / ops / ci-cd

# tạo prompt wbs cho pm

## promp wbs
"hãy viết wbs cho task sau với góc nhìn senior dev:
- chỉ giữ đúng các hạng mục tôi nêu, không mở rộng
- mỗi task gồm:
  - <task chính> (<hành động / chi tiết thực thi>) [điều kiện | phạm vi | giả định] <effort giờ thuận-nghịch>
- ước lượng thời gian thực tế cho mỗi task với effort số giờ cần thực hiện
- định dạng markdown, bullet '-', lowercase, ngắn gọn, không giải thích thêm"

## quy ước chung
quy tắc loại nhanh:
- cái gì phải làm → () : hành động sẽ thực thi
- cái gì có thể có / giới hạn → [] : điều kiện hoặc phạm vi áp dụng
- cái gì chưa biết, cần điền → <> : placeholder bắt buộc thay
- cái gì đã là thực tế → không ngoặc : tên thật, trạng thái hiện hữu
